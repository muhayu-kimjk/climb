화면 ID는 `SCR-번호` 형식입니다. 앞자리는 화면 묶음을 뜻합니다: 1 계약 등록, 2 계약 검토, 3 계약 체결, 4 보관함, 5 관리자. 업무 흐름 5단계(REQ-FLOW-13)의 단계 번호와는 같지 않습니다. [가정] 운영 검토 화면의 번호는 그 화면을 만들 때 정합니다. 프로토타입 HTML 파일 맨 위 주석에 같은 ID를 적습니다.

"시안" 열의 **완료**는 프로토타입 화면이 만들어진 것, **예정**은 아직 만들지 않은 것입니다.

## 1. 메뉴 구조

메인 메뉴는 **개요 → 계약 등록 → 계약 현황 → 보관함** 순서입니다(REQ-UI-14). 업무 흐름 5단계(계약 등록 → 계약 검토 → 계약 체결 → 운영 검토 → 계약 완료, REQ-FLOW-13)는 메뉴와 따로 갑니다. 계약 검토, 계약 체결, 운영 검토는 "계약 현황"에서, 계약 완료는 "보관함"에서 봅니다. KRDS 메인 메뉴(상단 가로 메뉴) 구조를 따르며, 하위 화면이 있는 메뉴는 누르면 아래로 하위 메뉴가 펼쳐집니다. 메뉴 줄 오른쪽 끝에는 "이용 안내"를 둡니다.

메뉴는 역할에 따라 다르게 보입니다. (REQ-AUTH-11 [가정]) 최고관리자에게는 아래 메뉴가 모두 보입니다(REQ-AUTH-14). 역할은 분야와 등급(담당자, 리더, 임원) 2단계이고, 영업지원, 정보보호, 고객지원, 재무의 리더와 재무 임원은 그 분야 담당자의 메뉴를 함께 봅니다(v0.22, REQ-AUTH-01, 18). 관찰자는 모두에게 보이는 메뉴만 봅니다.

```
CLIMB                                                         [이용 안내]
├─ 개요                         ← 로그인 후 첫 화면 (모두)
├─ 계약 등록                    ← 영업
│   ├─ 새 계약 등록              내용 작성, 임시 저장, 기안
│   └─ 내 등록 목록              내가 등록한 계약의 진행 상황 (임시 저장 삭제 포함)
├─ 계약 현황                    ← 모두 (하위 메뉴는 역할별)
│   ├─ 전체 진행 현황            검토 중, 체결 대기, 운영 검토인 모든 계약 (모두)
│   ├─ 검토 대기                 내 차례인 건 (②~⑤ 검토 역할, ⑥ 총무, ⑧ 영업지원)
│   ├─ 검토 완료                 내가 처리한 결재 (위와 같은 역할)
│   ├─ 체결 대기                 승인 후 오프라인 서명, 체결본 등록 (영업)
│   └─ 운영 검토 대기            ⑨ 운영 적용, ⑩ 재무 확인 차례인 건 (고객지원, 재무)
├─ 보관함                       ← 모두
│   ├─ 전체 계약                 반려, 승인, 체결된 모든 계약 → 계약 상세
│   └─ 만료 예정 계약            갱신 검토, 갱신 기안, 해지 기안 시작 (계약 상세, 해지 기안, 갱신 검토, 운영 변경 기안은 메뉴 없이 들어감)
└─ 관리자                       ← 관리자, 최고관리자 (정보보호 담당자와 리더는 접속 기록 점검만)
    ├─ 사용자 권한 관리          계정 정보와 권한 목록, 사용자 추가와 권한 수정, 권한 변경 이력
    ├─ 결재선 규칙               단계별 담당자, 대리 지정, 독촉 기준 일수 (금액 기준 없음)
    ├─ 열람 제한 관리            열람 제한 계약 목록, 걸기와 풀기, 변경 이력
    ├─ 가격 기준 관리            표준단가표, 할인율 한도, 적용 시작일, 품의 문서, 이력
    ├─ 거래처 관리               거래처 목록 고치기, 합치기
    ├─ 코드 관리                 조직 2단계, 서비스 3단계, 계약 유형 등 관리자 관리 코드값
    └─ 접속 기록 점검            이상 행위 알림, 월 1회 점검 결과, 분기 권한 검토, 접속 기록 조회 (정보보호, 관리자에게는 안 보임)
```
