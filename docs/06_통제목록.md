## 이 문서 읽는 법

이 문서는 climb의 통제를 한곳에 모은 통제 목록입니다. 표준 대응표(05)의 G-27 ①~⑤와 G-15 ①에 답합니다. 문서만 고치는 일이라 화면은 바꾸지 않습니다. 이 문서는 요구사항을 바꾸지 않습니다. 기획자가 받아들인 것만 01~05로 옮깁니다.

**장마다 담은 것**

| 장 | 담은 것 | 05의 어디에 답하나 |
|---|---|---|
| 1 | 통제 목록(RCM): 위험, 통제, 하는 사람, 경영자 주장, 주기, 남는 증거, 책임자 | G-27 ① |
| 2 | 핵심 자동 통제와 시험: 기대 동작, 시안 코드 위치, 되는 경우와 안 되는 경우의 시험 | G-15 ① |

**통제 목록을 만든 방법**

검토자 넷이 범위를 나눠 01~05와 시안 코드에서 통제를 뽑았습니다. 나눈 범위는 결재선과 결재, 영업 기회와 견적과 가격과 계약 등록과 기준 정보, 체결과 운영 넘김과 체결 후와 변경, 접근과 보안과 기록과 보고입니다. 둘 이상의 검토자가 같은 통제를 뽑은 것은 한 줄로 합치고 관련 ID를 모두 적었습니다(139개를 124개로). 그 뒤 목록을 다시 검토해 빠진 통제 8개를 더했습니다(132개). 검토 범위의 "변경"(해지, 연장, 운영 변경)은 05처럼 "체결 후"에 넣었습니다.

|---|---|

**핵심(★):** 매출 금액과 승인에 직접 걸려 감사에서 먼저 볼 통제입니다. [제안] 줄에도 ★을 붙였습니다. 정하면 핵심이 된다는 뜻입니다. 기준 정보에서는 첫 적재(CTL-87)만 ★입니다. 운영 중에 거래처를 확인하는 통제(CTL-80)와 제품과 기능을 바꾸는 통제(CTL-85)는 ★을 붙이지 않았습니다. 거래처는 뒤의 ②, ⑥, ⑧, ⑩ 확인을 거치고, 운영 중 변경은 관리자 변경 이력(CTL-117)과 설정 변경 점검(CTL-16 [제안])으로 보기 때문입니다. 이 판단도 재무팀이나 외부감사인 확인 때 함께 봅니다(7장 3번).

**하는 사람과 책임자:** 하는 사람은 01에서 이미 정했으므로 그대로 옮겼습니다. 책임자는 통제마다 누가 책임지는지이고, 기획자가 05 4장 24번을 정할 때까지 비워 둡니다. 05의 [제안]은 이미 정한 담당(3.6의 단계 담당, ③의 영업 리더와 COO, 보안의 정보보호 담당자)을 그대로 쓰는 것입니다.

**표시와 인용**

- [제안]은 이 문서가 권하는 것, [가정]은 회사 사정을 확인하지 못해 임시로 둔 것입니다. 01, 05의 표시와 뜻이 같습니다.
- ISO와 IEC 표준은 문장을 옮기지 않고 조항 번호와 우리말 요약만 적습니다. 금융감독원 자료도 원칙 번호와 뜻만 적습니다.
- 05처럼 금융감독원 원문과 문장 단위로 대조하지 않았습니다. 경영자 주장, 핵심 표시, 원칙 연결은 재무팀이나 외부감사인의 확인을 권합니다.
- 기획자 결정이 표준보다 앞섭니다. 표준이 더 요구하면 기획자 결정을 바꾸자고 하지 않고, 남는 위험(4장)이나 열린 빈 곳(G 번호)으로 적었습니다.

## 2. 핵심 자동 통제와 시험

05 G-15 ①에 답합니다. 1장에서 핵심(★)이고, 방식이 자동이나 IT 의존이며, 이미 있는(시안에 있음, 문서에만) 통제 45개를 모았습니다. 여기에 05 G-15가 안 되는 경우의 시험으로 꼭 든 "열람 제한이 새는 것"을 시험하려고 열람 제한 통제 4개(CTL-91, CTL-92, CTL-93, CTL-126, 핵심은 아님)를 더해 49개입니다. 05 2장대로 열람 제한은 목록, 검색, 통계 모두에 걸리므로 통계(CTL-126)도 넣었습니다. [제안] 통제는 기획자가 정한 뒤 이 장에 더합니다.

**읽는 법**

- 시안 코드는 정답지일 뿐입니다. 실제 시스템은 같은 결과가 나오게 서버에서 다시 만듭니다(04 2.3, 2.4).
- 시안은 브라우저 안에서만 돌아 모든 검사가 화면에만 있습니다. 그래서 안 되는 경우의 시험은 모두 화면을 거치지 않고 서버에 직접 조작한 요청을 보내는 방식으로 합니다. 05 G-15가 든 네 가지(화면 값 조작, 자기 결재, 열람 제한이 새는 것, 번호 빠짐과 겹침)가 모두 들어 있습니다.
- 04 3장의 "핵심 자동 통제 시험"(04 v0.19)이 이 장 전체를 가리킵니다. 아래 "04" 줄은 그 한 줄 말고 04에 따로 적힌 곳이 있는지입니다. 04는 2026-10-31 v0.19를 기준으로 보았습니다.
- 업무 담당자의 시험 확인: 핵심 통제 코드를 바꿀 때 업무 담당자(결재선과 가격은 영업지원, ⑩과 4번은 재무)가 이 시험 결과를 확인하는 것은 [제안]입니다. 기획자의 REQ-SEC-13 확정 결정(05 4장 12번)이 아직 열려 있습니다. 아래 표의 "업무 확인" 칸도 모두 [제안]이고, 05가 이름을 든 두 묶음 밖은 "정할 것"으로 두었습니다.

### AC-21 첨부 판과 지문

- **통제:** CTL-37 (1.5 결재)
- **기대 동작:** 계약서 초안, 조항 대비표, 체결본을 올릴 때마다 서버가 새 판 번호와 SHA-256 지문을 붙여 저장하고, 고치거나 지우는 길은 없다. ②~⑤가 끝난 판에 "결재한 판", ⑧에서 확인한 체결본에 "확인한 체결본"이 붙고, 결재 기록마다 결재자가 그때 본 판이 남는다.

  - 저장된 파일의 지문을 다시 계산했을 때 기록과 다름: 예외로 남김

- **서버에서 다시 확인할 것:** 판 번호, 지문, 결재자가 본 판은 서버가 정해 저장하고 화면 값을 믿지 않는다. 시안의 지문은 파일 이름과 올린 시각으로 만든 가짜 값이므로, 실제 시스템은 파일 내용으로 SHA-256을 계산한다.

- **되는 경우 시험:** 관리자가 사유를 적고 법무 담당자를 추가하면 첫 접속 전 상태가 되고, 이력 한 줄이 남는다.
- **안 되는 경우 시험:**
  - 영업이 권한 저장 요청을 직접 보냄: 거부
  - 다른 도메인 이메일, 대소문자만 다른 같은 이메일: 거부
  - 사유 빈칸: 거부
  - 이력에 전후 값 중 하나가 빠짐: 실패
  - 이력 고치기나 지우기 요청: 거부
- **서버에서 다시 확인할 것:** 역할, 도메인, 중복, 사유를 서버에서 다시 확인한다. 시안의 시연 기록 지우기는 실제 시스템에서 뺀다.
- **04:** 있음(3장 "권한")

### AC-43 자기 권한 못 바꿈

- **통제:** CTL-99 (1.10 접근과 보안)
- **기대 동작:** 바꾸는 사람과 대상이 같으면, 또 최고관리자가 아닌 사람이 최고관리자 권한을 주거나 빼거나 최고관리자 계정을 바꾸면 서버가 거부한다.
- **시안 코드 위치:** `admin-users.js`: `openEdit`, `rolesHtml`
- **되는 경우 시험:** 관리자 A가 관리자 B의 권한을 사유와 함께 바꾸면 저장된다.
- **안 되는 경우 시험:**
  - 관리자가 자기 줄의 수정 요청을 직접 보냄: 거부
  - 최고관리자가 아닌 관리자가 사용자 추가 창에 최고관리자 체크를 넣어 보냄: 거부(시안은 추가 창에서 이것을 다시 확인하지 않음)
  - 관리자가 조직 옮기기에 자기를 넣어 자기 조직을 바꿈: 시안은 막지 않음. 자기 조직이 바뀌면 ③ 리더가 바뀔 수 있어 막을지 정해야 함
  - 관리자 두 명이 서로 권한을 줌: 막지 않지만 분기 권한 검토에 보여야 함
- **서버에서 다시 확인할 것:** 저장 때 바꾸는 사람과 대상 계정을 서버에서 비교한다.
- **04:** 없음

### AC-44 사용 중지 계정 막기

  - Google 계정이 아직 살아 있어도 사용 중지면 로그인: 거부
  - 사용 중지 계정을 지우려 함: 지울 수 없음

- **서버에서 다시 확인할 것:** 로그인과 모든 요청에서 계정 상태를 확인하고, 사용 중지 때 열린 세션을 끊는다.
- **04:** 없음(3장 "로그인"에 이 내용이 없음)

### AC-45 분기 권한 검토

- **통제:** CTL-102 (1.10 접근과 보안)
- **기대 동작:** 검토 창의 숫자가 계정과 이력 전체에서 빠짐없이 계산된다. 저장한 결과는 분기마다 한 번이고 고칠 수 없으며, 기한이 지나면 강조된다.
- **시안 코드 위치:** `admin-logs.js`: `accessSummary`, `openQuarter`, `quarters`, `renderQuarters`
- **되는 경우 시험:** 분기가 끝난 뒤 정보보호 담당자가 결과를 남기면 검토한 사람, 일시, 결과가 남고 결과 남기기 버튼이 사라진다.
- **안 되는 경우 시험:**
  - 관리자가 검토 저장 요청을 직접 보냄: 거부
  - 같은 분기에 두 번 저장: 거부
  - 사유 없는 권한 변경이 1건 있음: 검토 창에 1건으로 보여야 함
  - 정보보호와 관리자 역할을 함께 가진 사람이 자기 변경이 든 분기를 검토: 지금 규칙은 막지 않음(G-11, G-24)
  - 나중에 다시 열면 숫자가 달라짐: 검토 때 본 목록을 저장하지 않아서(G-23, CTL-114)
- **서버에서 다시 확인할 것:** 검토 자료는 서버에서 계산하고 기록은 덧붙이기만 한다. 점검 일정 계산은 서버 예약 작업 하나로 한다(04 2.5).
- **04:** 있음(3장 "접속과 작업 기록", 2.5)

### AC-46 결재 기록은 덧붙이기만

- **서버에서 다시 확인할 것:** 통계 합계는 서버가 보는 사람의 열람 권한으로 계산한다(04 2.5 "가림은 서버에서").

## 3. 지켜야 할 법과 규정

## 6. AI를 쓰기 전 문턱

05 G-27 ④에 답합니다.

- **지금:** REQ-ENV-12(확정, v0.21)대로 climb에는 AI 에이전트, 요약, 챗봇 같은 AI 기능이 없습니다. 시스템 안에서 AI가 계약 정보를 처리하거나 외부 AI로 정보를 보내지 않습니다. 그래서 지금 적용할 AI 통제는 없습니다. 설계와 개발에 쓰는 AI 도구는 5장 마지막 줄에서 봅니다.
- **열려 있는 아이디어:** 01 8장 "검색 창의 AI 에이전트 입력"(v0.60 기획자 의견)은 REQ-ENV-12를 바꾸는 일이라 보안, 개인정보, 사내 AI 사용 규정과 함께 정하기로 되어 있습니다.
- **[제안] 문턱:** 이 아이디어를 실행하기로 정하기 전에 아래를 넘습니다. 01 8장 AI 행에는 이 조건만 더합니다.

| 문턱 | ISO/IEC 42001 조항(요약) | 할 일 |
|---|---|---|
| 쓰는 범위 | 4.1 조직과 맥락: AI를 어디에 쓰고 누가 영향을 받는지 정함 | 검색 창 AI가 볼 화면과 데이터의 범위, 열람 제한 계약을 넣는지를 정함 |
| AI 정책 | 5.2 AI 정책: 경영진이 AI 사용 원칙을 정함 | 사내 AI 사용 규정이 climb에 맞는지 확인 [가정: 규정이 있음] |
| 위험과 영향 평가 | 6.1 위험과 기회 대응(AI 위험 평가와 처리), 6.1.4 AI 시스템 영향 평가 | 계약 정보, 직원 정보, 열람 제한 계약이 AI 입력으로 어디까지 가는지, 틀린 답이 결재와 회계에 줄 영향을 평가하고, 정보보호 리더와 컴플라이언스가 결과를 확인 |
| 공급자 약관 | 부속서 A.10.3 공급자 | 입력을 학습에 쓰지 않음, 입력과 결과를 국내에 보관(REQ-SEC-16), 처리위탁 문서(개인정보 보호법 제26조), 입력과 결과의 기록을 남김(REQ-AUTH-13과 같은 방식). 이 조건을 약관이나 계약으로 보장할 때만 외부 통신 허용 목록(REQ-SEC-12)에 넣음 |

- 이 문턱을 넘기 전까지 REQ-ENV-12는 그대로입니다.

## 7. 다음에 할 일

[제안] 아래 순서를 권합니다.

1. **책임자 정하기(05 4장 24번):** 정하면 1장의 책임자 칸과 4장의 수용 책임자 칸을 채웁니다. 05의 [제안]은 이미 정한 담당(3.6의 단계 담당, ③의 영업 리더와 COO, 보안의 정보보호 담당자)을 그대로 쓰는 것입니다.
2. **REQ-SEC-13 확정(05 4장 12번):** 정하면 2장의 "업무 확인 [제안]"을 확정으로 바꾸고, 2장 끝의 "04에 따로 적힌 곳이 없는 것"을 04 3장에 옮깁니다.
3. **재무팀이나 외부감사인 확인:** 경영자 주장, 핵심 표시, 원칙 연결이 맞는지 확인받습니다. 기준 정보의 CTL-80과 CTL-85에 ★을 붙이지 않은 판단("이 문서 읽는 법"의 핵심 설명)도 함께 봅니다. 01 3.6.1과 05의 안내처럼 금융감독원 원문과 문장 단위로 대조하지 않았습니다.
4. **법무 확인:** 3장의 "법무 확인 필요"와 "원문 확인 필요"(상법 보존 기간을 세는 시작, 청탁금지법의 정당한 권원, 민법의 해제와 해지 조항, 노사협의회 해당 여부, K-IFRS 제1115호는 재무)를 묻습니다.
5. **함께 맞추기:** 통제가 바뀌면(01의 REQ 추가나 변경, 05의 G 반영, 04의 서버 할 일) 같은 날 이 목록도 고칩니다. 새 [제안]이 정해지면 상태를 바꾸고, 핵심 자동 통제면 2장에 시험을 더합니다. 데이터가 바뀌는 것은 데이터 정의서(03)도 함께 고칩니다.
6. **매년:** 3장의 법 개정 날짜(다시 보기), 4장의 다시 볼 때, 5장의 매년 확인을 한 번에 봅니다(ISMS-P 1.2.3, 1.4.1).
7. **새 빈 곳 올리기:** [제안] 만료 계약의 서비스 닫기(해지의 ⑨처럼 확인과 기록)를 05에 새 빈 곳으로 올려 기획자가 정합니다. 정하기 전까지는 4장 표 아래의 후보로 둡니다.
